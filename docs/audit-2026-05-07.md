# CatVox Repository Audit — 2026-05-07

Full-stack review of the CatVox AI repository covering iOS app (Swift), Cloud
Functions backend (TypeScript), Terraform IaC, CI/CD (GitHub Actions), project
configuration (XcodeGen / Makefile), documentation, and bootstrap scripts.

---

## 🔴 Critical / High Severity

### 1. Terraform CI PR comments are empty — `steps.<id>.outputs.stdout` never populated

**File:** `.github/workflows/terraform.yml` (lines ~100–130)

The `plan` job attempts to read `steps.validate.outputs.stdout` and
`steps.plan.outputs.stdout` inside a JavaScript GitHub Action (`actions/github-script`).
GitHub Actions `run:` steps do **not** automatically expose `stdout` as a step
output — it must be explicitly written via `$GITHUB_OUTPUT`.

**Impact:** The validate and plan output values are always empty strings. The PR
comment's "Validate" and "Show Plan" collapsible sections are blank. The plan
still runs and correctly fails the job on error (`if outcome === 'failure'`),
but no plan detail reaches the PR.

**Fix:** Pipe `terraform plan` output to a temp file, then load it into a step
output:

```yaml
- name: Terraform Plan
  id: plan
  run: |
    make terraform-ci-plan > plan.txt
    {
      echo 'stdout<<EOF'
      cat plan.txt
      echo 'EOF'
    } >> "$GITHUB_OUTPUT"
```

Same pattern for `validate`.

### 2. `xcodeVersion: "26.4"` in `project.yml` likely wrong

**File:** `project.yml` line ~8

The CI runs on `macos-15` with Xcode 16.x. `xcodeVersion` maps to the
`LastUpgradeCheck` value in the generated `.xcodeproj/project.pbxproj`:
`26.4` → `2640`. No shipped version of Xcode corresponds to 26.4.

AGENTS.md documents `26.4` as the expected value but references Xcode 16
elsewhere (macOS 15 runner, iOS 17+ SDK).

**Impact:** Xcode may prompt "update project settings" on every open. Risk of
unintended build-setting migration when the project is opened in a real Xcode
version.

**Fix:** Verify the actual Xcode version in use and set `xcodeVersion` to match
(e.g. `"16.4"` → `1640`). Update AGENTS.md table accordingly.

### 3. PR comment script references `context.actor` which is undefined

**File:** `.github/workflows/terraform.yml` line ~120

```javascript
`*Triggered by @${context.actor} · \`${context.eventName}\`*`
```

The `context.actor` property is available only in reusable workflow contexts.
In a standard workflow, this should be `github.actor` or
`github.triggering_actor`.

**Impact:** The attribution line renders as `Triggered by @undefined · …` in
every PR comment.

**Fix:** Replace `context.actor` with `github.actor`.

## 🟠 Major

### 4. Hardcoded project-specific service account emails in Cloud Functions

**Files:**
- `functions/src/signedUrl.ts` (line 20)
- `functions/src/analyse.ts` (line 43)

```typescript
serviceAccount: 'catvox-backend-sa@kathelix-catvox-prod.iam.gserviceaccount.com'
```

The SA email is hardcoded with the specific project ID. Deploying to a
different GCP project (e.g. the planned Dev/Prod split — TRD §9) requires
source changes.

**Fix:** Derive the email at runtime from `process.env.GCLOUD_PROJECT`:

```typescript
serviceAccount: `catvox-backend-sa@${process.env.GCLOUD_PROJECT}.iam.gserviceaccount.com`
```

Also consider centralising the project ID for all SA references.

### 5. Hardcoded Cloud Run endpoints in iOS client

**File:** `CatVox/Services/GCPService.swift` lines ~89–91

```swift
static let signedURL = URL(string: "https://getsigneduploadurl-pdkw5uifga-uc.a.run.app")!
static let analyse   = URL(string: "https://analysevideo-pdkw5uifga-uc.a.run.app")!
```

The hash (`pdkw5uifga`) is deterministic for Firebase Functions 2nd gen and
should remain stable across redeploys to the same project. However:

- It is project-specific — a different GCP project produces a different hash.
- There is no environment-selectable endpoint mechanism in the app. The
  planned Dev/Prod split will require changes to these URLs.

**Fix:** Consider reading backend endpoints from `Info.plist` build settings
(like PostHog config) so they can vary between Debug and Release builds or
between Dev and Prod environments.

### 6. TOCTOU race in quota enforcement

**File:** `functions/src/usageGuard.ts`

`checkUsageAvailable()` performs a non-mutating Firestore read.
`incrementUsage()` (which actually consumes the quota unit) is called only after
the Vertex AI call — potentially ~30 seconds later.

Two concurrent requests near the daily limit can both pass the pre-check.

**Status:** Acknowledged in TRD §9 ("Quota Race Hardening" — future work).

### 7. Quota increment failure after Vertex AI cost incurred

**File:** `functions/src/analyse.ts`

```typescript
const parsed = await getAnalysisPayload(() => callGemini(projectId, gcsUri, mimeType));
await incrementUsage(userId);   // ← Firestore write; can fail
res.status(200).json(parsed);
```

If `incrementUsage()` throws (e.g. Firestore transient error, permission
issue), the function returns HTTP 500. The Vertex AI call was already made and
billed, but the user gets no result and no quota was consumed. On retry the
user effectively receives a free scan.

### 8. `alert_email` variable has no default — blocks interactive Terraform apply

**File:** `terraform/variables.tf` (final variable block)

`var.alert_email` has no `default`. CI passes it via `TF_VAR_alert_email`, but
running `make terraform-apply` locally will block on an interactive prompt
unless `alert_email` is set in `terraform.tfvars`.

**Fix:** Either add a default (empty string, with monitoring.tf gated on
non-empty) or document that `terraform.tfvars` must include this value for
local apply to succeed.

---

### 9. Client/server timezone mismatch in quota reset logic

**Files:**
- `CatVox/Models/ScanQuotaStore.swift` — uses `DateFormatter` in **local** time
- `functions/src/usageGuard.ts` — uses `Date().toISOString().slice(0, 10)` in **UTC**

A user in a UTC−12 timezone could see "5 scans remaining" on the client while
the server has already reset or not yet reset, depending on the time of day.

**Fix:** Use UTC consistently on both sides, or accept the discrepancy and
document it as expected behaviour.

### 14. `signedUrl.ts` does not sanitise the client-supplied filename

**File:** `functions/src/signedUrl.ts`

```typescript
const objectName = `${randomUUID()}-${filename}`;
```

If `filename` contains `/` or special characters, GCS stores them literally
(no directory traversal risk — GCS has no real directories). This complicates
bucket listing and lifecycle management. No security impact.

### 15. `SavedScanRow` loads thumbnail synchronously on the main actor

**File:** `CatVox/Views/Home/SavedScanRow.swift`

```swift
if let image = UIImage(contentsOfFile: ScanHistoryStore.thumbnailURL(for: scan).path) {
```

`UIImage(contentsOfFile:)` blocks the calling thread. For small JPEG thumbnails
this is fast, but a long history list will degrade scroll performance.
Consider an async image loader for robustness.

### 16. `Makefile` `terraform-apply` runs plan twice redundantly

**File:** `Makefile` (terraform-apply target)

```makefile
terraform-apply:
    @cd terraform && terraform init
    @cd terraform && terraform plan -no-color   # ← shown, then discarded
    @cd terraform && terraform apply -no-color  # ← shows its own plan
```

Use `terraform plan -out=plan.tfplan` and `terraform apply plan.tfplan` instead
to run `plan` once.

### 19. Inconsistent env var naming for PostHog configuration

- **.env:** `POSTHOG_PROJECT_TOKEN`

confuse a developer setting up local overrides.
